XAI Connect 文档

使用标准 OIDC Authorization Code + PKCE，把 xai.run 登录安全地接入你的服务端应用。

本页导航 接入前提 创建应用 登录流程 安全说明 运维说明

接入前提

接入项目需要有可信服务端，用于保存 Client Secret、state、nonce、code_verifier 和本地 Session。

  • 回调地址必须是公网可访问的精确 HTTPS URL。
  • 纯 SPA、原生移动端和桌面客户端需要增加自己的后端或 BFF。
  • 客户端注册使用 client_secret_basic，不支持 client_credentials。

创建应用并获取凭证

  1. 使用 Discourse 账号打开控制台并创建应用。
  2. 填写应用名称、用途说明、回调地址和已验证域名。
  3. 安全策略默认强制校验 PKCE + nonce；只有确实需要兼容旧客户端时，才在应用编辑页关闭该校验。
  4. 应用上线后，在详情页查看 Client ID，并按需确认身份后查看 Client Secret。

Client Secret 只应保存于接入项目服务端的密钥管理系统或受保护环境变量中。兼容模式仍会校验 state、回调地址和授权码流程，建议尽快恢复 PKCE + nonce。

登录流程：Authorization Code + PKCE

接入方应优先读取 Discovery，不要在代码中散落硬编码端点。

GET https://connect.xai.run/.well-known/openid-configuration

Authorization: https://connect.xai.run/oauth2/auth
Token:         https://connect.xai.run/oauth2/token
UserInfo:      https://connect.xai.run/userinfo
  1. 服务端生成一次性的 state、nonce 和 code_verifier。
  2. 浏览器携带 S256 code_challenge 跳转到 Authorization Endpoint。
  3. 回调后服务端校验 state，用 code 和 verifier 换取 Token。
  4. 验证 ID Token 的签名、Issuer、Audience、Nonce 和有效期，再建立自己的 Session。

安全说明

  • 不要把 Client Secret、Access Token、Refresh Token 或 code_verifier 放进浏览器、URL、日志或 Git。
  • 不要把 Access Token 当作项目自己的登录 Cookie。
  • 严格校验 Issuer、Audience、Nonce、签名算法和 Token 有效期。
  • 轮换 Secret 后旧 Secret 会立即失效，应同步更新服务端密钥。

运维说明

生产环境只暴露 HTTPS 入口，PostgreSQL、Redis 和 Hydra 管理端点应留在受控网络内。

升级或恢复后检查 /healthz、/readyz、Discovery 和一个测试客户端的 PKCE 流程。
